# Account search

`GET /entries/search?q=...&folder_id=...&sort=...&limit=100&cursor=...` searches active names in the signed-in account's private libraries. Omitting `folder_id` or passing the default Files library ID searches across all of the account's libraries. Passing a named library or subfolder ID searches its descendants, excluding the folder itself. Search excludes library roots and Trash. A missing, foreign, trashed, or non-folder scope returns `404 not_found`. Each hit includes the entry and its containing folder path, starting at its library root. The default root has an empty name in search paths and appears as **Files** in the browser. The response has `items`, `next_cursor`, and `has_more`.

Matching uses a literal substring after NFC normalization and Unicode lowercase conversion. `%` and `_` are ordinary characters. Matching uses Unicode lowercase without full case folding or locale-specific casing. By default, results sort by converted name, then converted containing path, then entry ID. The sort parameter accepts `name_asc`, `name_desc`, `location_asc`, `location_desc`, `size_asc`, `size_desc`, `modified_asc`, and `modified_desc`. Location sort uses the displayed library name at the start of each path. An invalid sort returns `400 invalid_sort`.

The query must contain 1 to 255 UTF-8 bytes and no control characters. The page limit is 1 to 100, with 100 as the default. Cursors are signed, bounded, and tied to the account, exact query, folder scope, sort order, and active tree state. A changed tree returns `409 listing_changed`; restart at the first page. Search reads the live tree for each request, so a new search reflects renames, moves, and deletions.

The `q` hash parameter records the search query. Search paging and scroll stay in the current browser history entry. Opening a containing folder adds an entry; Back restores the previous search with fresh results and no selection. A copied search URL starts on its first page. Invalid or changed cursors restart the search with a notice.
